# 魔精大融合

轻量、无需安装依赖的网页合成游戏。玩家控制落点，让完全相同的魔精在物理碰撞中融合，并在容器触及危险线前获得更高分数。

游戏可直接部署到 GitHub Pages。物理模拟使用项目内置的 Matter.js 0.20.0，不依赖外部 CDN，也没有前端构建步骤。

## 游戏模式

### 无尽模式

- 使用路线Ⅰ–Ⅲ。
- 每次显示下一只魔精。
- 普通投放只会出现一至三阶魔精。
- 在 3 秒窗口内连续融合会提高连击倍率，最高为 3 倍。
- 连击达到指定阶段后，稀有魔精会加入后续队列。
- 两只同路线五阶魔精相撞时清除并获得高额分数。

### 双链融合

- 使用路线Ⅳ–Ⅴ，稀有魔精规则不变。
- 同时预告后续两只魔精，加强落点规划。
- 交替完成两条路线的融合会积累共鸣；只经营单一路线时，共鸣会逐渐衰减。
- 最近的融合记录越平衡，计分倍率越高；路线明显失衡时不再获得平衡加成。
- 每局持续生成双目标任务，包括交替融合、限定投放次数、指定阶位与场上共存目标。
- 两条路线的五阶魔精同时稳定存在时会成对清除，并获得专属高分奖励。

## 基础规则

- 点击、触摸或按空格投下当前魔精；鼠标、触摸移动以及方向键可调整落点。
- 只有完全相同的魔精才能融合，融合后进入该路线的下一阶。
- 稀有魔精再次相撞时只会清除并奖励额外高分。
- 魔精刚投下或弹跳经过危险线不会立即失败；只有稳定停留在线上方约 5 秒才会结束本局。
- 6 秒内没有主动投放时，当前魔精会自动落下。
- 两种模式分别保存本机最高分，图鉴进度和新手引导状态由两种模式共用。

## 界面与音效

- 游戏物理世界固定为 `690 × 800`，桌面端和移动端都会等比缩放，魔精不会因屏幕比例而被压扁。
- 双链信息区在移动端采用紧凑两行布局，位于危险线下方，目标内容可以完整显示。
- 右上角 `♪` 按钮可以开启或关闭音效，设置会保存在当前浏览器。
- 桌面端使用 Web Audio 播放合成音效；触屏设备使用浏览器原生 WAV 播放通道，提高 Android 与 iOS 浏览器兼容性。
- 音效包含投放、落地、融合、终阶清除、稀有奖励、双链清除、任务完成、危险线警告和游戏结束。
- 移动浏览器需要一次玩家触摸才能允许网页发声；音量由手机的媒体音量控制。

## 页面功能

- 完整主菜单与模式选择。
- 暂停、重新开始和游戏结束流程。
- 永久图鉴与收集进度。
- 规则说明与新手引导。
- 无尽模式、双链融合两张最高排行榜。
- 无需登录的匿名设备身份及可选排行榜昵称。

## 本地运行

仅测试游戏本体时，可以直接打开 `index.html`。

若要同时测试排行榜，建议从项目根目录启动本地 HTTP 服务，例如：

```powershell
python -m http.server 8000
```

然后访问 `http://localhost:8000`。排行榜 Worker 的 `ALLOWED_ORIGINS` 也需要包含该来源；`file://` 页面不适合测试跨域排行榜接口。

## 匿名最高排行榜

游戏仅为无尽模式和双链融合保存全球最高排行榜。

- 浏览器首次运行时会生成随机设备 ID 和本地密钥，不要求登录。
- 每个设备、每种模式只保留一个最高分，较低成绩不会覆盖已有记录。
- 玩家可以设置 2–12 字的排行榜昵称；匿名设备短码仍作为不可变身份保留。
- 清除浏览器数据或更换浏览器后，会形成新的匿名设备身份。
- 断网或接口暂时不可用时，最高成绩会先缓存在本机，恢复连接后自动补交。
- 排行榜服务尚未配置时，游戏本体和本地最高分仍可正常使用。

Cloudflare Worker、D1 数据库结构、迁移文件和接口测试位于 `worker` 目录。部署步骤见 [`worker/README.md`](worker/README.md)。部署完成后，将 Worker 的 HTTPS 地址填入 [`leaderboard-config.js`](leaderboard-config.js)。

排行榜采用适合休闲游戏的基础防护，包括设备密钥哈希、来源白名单、提交频率限制、成绩范围校验和单设备最高分覆盖。由于物理与计分仍在浏览器中运行，它不属于竞技游戏级反作弊。

## GitHub Pages 部署

1. 将本目录的全部文件上传到 GitHub 仓库。
2. 打开仓库的 **Settings → Pages**。
3. 选择从 `main` 分支的根目录发布。
4. 等待 GitHub Pages 完成部署后访问生成的网址。

素材由页面直接从 `1阶`、`2阶`、`3阶`、`4阶`、`5阶` 和 `unique` 文件夹读取，目录结构需要保持不变。

### 更新已经部署的网页

修改前端后，覆盖仓库中的对应文件并提交即可。大部分界面、规则、物理和音效更新只需要重新上传 `index.html`；排行榜接口配置变更还需要上传 `leaderboard-config.js`。

```powershell
git add index.html leaderboard-config.js README.md
git commit -m "更新游戏版本"
git push
```

GitHub Pages 发布后，如果手机仍显示旧界面，请强制刷新或清除该网站的缓存。若重新打开音效时显示“移动音效已开启”，说明触屏音效版本已经加载。

Worker 或数据库代码发生变化时，需要按照 `worker/README.md` 单独重新部署；单纯更新 `index.html` 不需要重新部署 Worker。

## 项目结构

```text
大魔精/
├─ index.html                 游戏界面、规则与玩法逻辑
├─ matter.min.js             本地物理引擎
├─ leaderboard-config.js     排行榜接口地址
├─ 1阶/ … 5阶/               普通魔精素材
├─ unique/                    稀有魔精素材
└─ worker/
   ├─ src/index.js           Cloudflare Worker 接口
   ├─ schema.sql             D1 初始数据库结构
   ├─ migrations/            数据库升级文件
   ├─ test.mjs               后端接口测试
   └─ wrangler.toml          Cloudflare 部署配置
```
